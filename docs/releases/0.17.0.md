# Cutaway 0.17.0 — library, legibility, and rendering lifecycle

Android versionCode: **22**. Package: `com.cutaway.explorer`.

## Changes

- Anchored adaptive AdMob banner below the library's scroll area, using unit
  `ca-app-pub-6279186647593327/5209257311`. The slot is separated from content,
  respects safe-area insets, and unmounts on keyboard opening, route blur,
  app backgrounding, or a Remove Ads entitlement. No new ad placement was
  added to the 3D viewer or quiz.
- Shared UMP consent preparation before banner/interstitial SDK requests,
  delayed measurement initialization, and privacy options in Settings when
  the SDK requires them. Paid-user state must finish hydrating first.
- Localized library search across the current language's title, subtitle,
  summary, and category; multiple words combine with AND. Existing category
  filtering, a clear action, result count, and empty-state reset work together.
- Light/dark text and object accent foregrounds now meet the tested 4.5:1
  text-contrast threshold on neutral and tinted surfaces. Decorative accent
  colors and existing object geometry are unchanged.
- A cancellable frame loop pauses for unfocused, backgrounded, zero-sized,
  and fully covered viewers. It resumes without counting suspended time
  toward animation, and disposal cancels the scheduled frame.

## Verification

- `npm run check`: passed, including TypeScript, nine new product/ad tests,
  eight monetization-policy tests, catalog/localization validation for all
  28 objects, model regressions, and the existing APK-workflow tests.
- `node tools/product-ui-test.mjs`: passed on ten browser screens in English
  and Indonesian, light/dark themes, including narrow 360-pixel layout.
  No page errors or low-contrast active text were found in those screens.
- Instrumented browser draw calls stayed unchanged during a 1.2-second
  covered-viewer interval and while the previous viewer was behind a quiz;
  drawing resumed after navigation back.
- The pre-existing model/content edits in the working tree were preserved.
- Android `:app:packageReleaseBundle`: successful, including release lint.
  Bundletool 1.18.3 validated the produced bundle. Its packaged manifest has
  version 0.17.0 / code 22, minSdk 24, targetSdk 36, the correct AdMob app ID,
  delayed measurement enabled, and no debuggable flag.
- Bundle-byte verification matched all 56 model copies and the decoded
  pixels of all 28 unique object icons to current source files. The packaged
  JavaScript matches the newly generated release bundle and includes the new
  banner/search code. All four ABIs are present. All 44 packaged 64-bit native
  libraries have at least 16 KiB load-segment alignment; the bundle config
  requests `PAGE_ALIGNMENT_16K`.

Browser coverage is not proof of native ad delivery or physical-device GPU
performance. Native banner fill, UMP console messages, and live purchases
still require device/account verification; final Google review is pending. Existing
interstitial timing/race findings from the full audit were not all addressed
by this scoped upgrade.
